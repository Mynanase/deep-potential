# OpenResearch 工作约定 — dpjax-phase2

本文件记录仓库的通用研究工作约定。当前问题、实验设置和结果见
[近期进展](progress.md)及相关代码，不在这里重复。

开始研究任务前先阅读本文件，并用 `orx skill` 加载当前操作手册，按任务需要阅读相关模块。
OpenResearch 应用会话若提供 `.openresearch/agent/autoresearch-local.md`，会话配置以该文件为准；
项目、节点、运行状态仍通过 orx 实时查询，不把文档中的旧状态当作当前事实。

## 实验与提交

- 检验新假设时，先创建实验节点，再在其分支上修改、验证和提交，通过 orx 启动运行。
  改动限于该研究问题，新增脚本和配置也必须纳入提交；运行只读取提交快照。
- 尚未回答研究问题的节点可在原分支修复、提交后重跑。节点一旦建立基线或回答假设，
  其代码与历史即冻结；后续改动建子节点。结果不理想不构成原地修复的理由，
  后一次运行报错也不能解除冻结。
- 纯文档、只读分析以及公式、单位、输入等局部检查不需要实验节点。
  用于检验研究假设或比较候选方案的训练与评估必须进入实验树。
- 并列方案从共同父节点分支；后续实验从其实际依赖的结论继续。
  父子关系表达研究上的承接。

## 运行与比较

各研究阶段可以有自己的 runner；同一组对比实验保持一致。
比较时检查实际输入、环境、训练预算和评估方式，明确本次允许改变的因素。
超参数与行为差异写入已提交的代码或配置，不通过临时启动命令或外部环境变量隐藏改动。

启动前确认提交包含所需文件，并按当前操作手册核对运行环境和计算资源。
运行完成后读取日志，判断它是否回答研究问题，再决定修复、继续比较、开展后续实验或停止。
处理完成事件时核对所有新结束的运行，避免遗漏；修复上限和停止条件按当前手册执行。

更新节点说明时保留原假设、具体改动和来源运行，再补充结论与限制。
`orx exp desc` 的写入会替换整段说明，不能把它当作自动追加。

## 证据与记录

- 运行状态只说明执行进度，不证明科学结论。运行结果从 `orx logs` 指向的完整日志取证，
  不凭短预览、记忆或转述作判断。
- 运行应记录实际配置、关键指标和结果摘要。比较前检查相关提交的差异，
  报告中注明来源运行，并分清已验证事实、推断和待解决项。
- 完成一次判断后更新 `docs/progress.md` 的当前状态；详细过程保留在运行日志、Git 和相关报告中。
- OpenResearch 会话中的文件和运行引用遵循应用提供的链接格式。
  其他客户端使用其支持的可点击引用，不假定 OpenResearch 标签能在所有客户端显示。

## 产物与归档

报告、图、CSV、PDF 等持久产物写入项目实际 Artifacts 目录，按研究主题组织；
目录以会话配置或项目 Artifacts 面板显示的路径为准。
链接中的 `artifacts/` 是引用前缀，不代表仓库内同名目录会自动被 Web 收录。

生成脚本与图放在一起，报告使用可解析的相对链接。写报告和绘图前分别阅读
`orx-reports`、`orx-figures` 模块；临时文件和中间日志留在产物目录之外。
面向读者的最终报告同时归档到仓库并在 README 链接，相关图表一并保留，确保引用仍然有效。
Web 可见性与仓库归档分别检查，不把其中一项当作另一项已完成的证明。

回复和文档遵循根目录 AGENTS.md 的表达约定：先说结果或当前问题，再说明依据、限制和下一步，
不贴操作流水账。
